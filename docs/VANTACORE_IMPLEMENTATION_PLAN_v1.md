# VantaCore Implementation Plan v1

Source of truth: `VANTACORE_UPGRADE_PLAN_v1.md`
Plan date: 2026-05-30
Direction: open-core, client-side-first, developer-focused
Primary boundary: keep the free web demo 100% client-side.

## Implementation Boundaries

Do not build these yet:

- API endpoints, hosted compression, auth, quotas, or billing.
- Full payment, backend account, subscription, or Google auth system.
- Heavy license enforcement or advanced Pro activation.
- Full UI redesign or dashboard rewrite.
- Cloud sync or backend history.
- Any change that weakens the current Memory Capsule compression engine.

Keep changes staged and reversible:

- Start with docs, positioning, local-only limits, branded free exports, and clean future hooks.
- Preserve the current free demo trust promise: no upload required, no server processing, browser/local storage only.
- Treat soft limits as product framing, not abuse-proof enforcement.

## Phase 2 - Free Demo Guardrails

Goal: add the first freemium framing layer without backend complexity.

Tasks:

- [ ] Add a soft local free limit:
  - 5 compressions/day
  - stored in `localStorage`
  - reset by local calendar date
  - visible remaining compression count
  - no login/backend/account
- [ ] Add free export branding:
  - Markdown/TXT exports include VantaCore attribution.
  - Exports include "Generated by VantaCore - Portable Memory Capsules for LLMs."
  - Exports include "Compress massive AI sessions into portable memory capsules. 100% client-side."
  - Exports state: "VantaCore does not claim ownership of your input or output content."
- [ ] Add future Pro hooks without implementing Pro:
  - export branding wrapper can later support no-branding Pro mode
  - no license checks
  - no payment checks
- [ ] Formalize local history:
  - Free history keeps the last 20 local compressions.
  - Stored only in browser/local storage.
  - Basic restore/copy/delete/clear.
  - Future Pro can expand to unlimited local history, search/filter, workspaces, pinned capsules, advanced export from history.

Files likely to change:

- `frontend/src/stores/compressionStore.ts`
- `frontend/src/components/CompressButton.tsx`
- `frontend/src/components/OutputSection.tsx`
- `frontend/src/components/HistorySidebar.tsx`
- Optional helper module for usage/export branding.

Risks:

- Users may mistake the soft local counter for secure quota enforcement.
- Branded exports may feel heavy if attribution is too large.
- History restore may store too much content in localStorage for very large capsules.

Mitigations:

- Keep limit copy transparent: "local free compressions".
- Keep export branding clear and minimal.
- Store only the last 20 local compression records.

Acceptance criteria:

- A user can see remaining free compressions before running the engine.
- The sixth compression on the same local day is blocked by the free UI layer.
- Markdown/TXT exports include attribution and ownership disclaimer.
- JSON export metadata includes generator information.
- Compression output itself remains unchanged in the on-page textarea.
- Current validation benchmark does not regress.
